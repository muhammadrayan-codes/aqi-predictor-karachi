# Pearls AQI Predictor (Karachi)

## Project Overview

This repository implements an **end‑to‑end, serverless AQI forecasting pipeline** for Karachi. It fetches historic and real‑time air‑quality and weather data from the **Open‑Meteo** APIs, engineers a rich set of features, stores them in a Parquet‑based feature store, trains three horizon models (24 h, 48 h, 72 h) with **scikit‑learn** (Ridge, Random Forest, XGBoost) wrapped in a custom `AQIDeltaRegressor`, logs experiments and registers models in **MLflow**, and serves real‑time predictions through a **Streamlit** dashboard.

✨ **Live demo:** https://aqi-predictor-karachi-vdtnfg6rzatxqniuho9vj2.streamlit.app/

> **UI updates:** Hero badge now shows only “LIVE TELEMETRY” and the subtitle no longer contains the leading slashes, providing a cleaner look.

## Technology Stack
- **Python** 3.11+
- **Data handling**: pandas, numpy, pyarrow
- **ML**: scikit‑learn, xgboost, tensorflow (optional for future deep‑learning extensions)
- **Experiment tracking & model registry**: mlflow (hosted on DagsHub)
- **Orchestration**: GitHub Actions (hourly feature pipeline, daily training pipeline)
- **Web UI**: Streamlit (real‑time dashboard)
- **API** (optional): FastAPI / uvicorn for external serving
- **Explainability**: shap (used for feature‑impact visualisation)
- **Visualization**: plotly, matplotlib, seaborn
- **Version control & CI**: git, GitHub Actions

## How to Run Locally
1. **Clone the repo** and create a virtual environment:
   ```bash
   git clone https://github.com/muhammadrayan-codes/aqi-predictor-karachi.git
   cd aqi-predictor-karachi
   python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```
2. **Set up environment variables** (`.env` based on `.env.example`).
3. **Back‑fill historic data** (run once):
   ```bash
   python backfill_pipeline.py
   ```
4. **Start the hourly feature pipeline** (or let GitHub Actions do it):
   ```bash
   python feature_pipeline.py   # will append the latest hour to data/features.parquet
   ```
5. **Train the models** (pre‑train on 90 days):
   ```bash
   python training_pipeline.py --pretrain
   ```
   Subsequent daily runs can be executed without the flag to train on the most recent 24 h.
6. **Launch the dashboard**:
   ```bash
   streamlit run app.py
   ```

## CI/CD (GitHub Actions)
- **hourly_feature_pipeline.yml** → runs `feature_pipeline.py` every hour and pushes the updated Parquet file.
- **daily_training_pipeline.yml** → runs `training_pipeline.py` nightly, logs metrics to MLflow, and registers the best model.

## Data Sources
- **Open‑Meteo Air‑Quality API** – provides hourly pollutant concentrations (`pm2_5`, `pm10`, `co`, `no2`, `so2`, `o3`, `dust`, `aqi`, `uv_index`).
- **Open‑Meteo Weather API** – supplies temperature, humidity, wind, pressure, solar radiation, boundary‑layer height, vapour‑pressure‑deficit, etc.

## Model Registry
All trained models are logged and **registered** in MLflow under names `aqi_karachi_target_aqi_24h`, `..._48h`, `..._72h`. You can view them in the *Models* tab of the MLflow UI on DagsHub.
